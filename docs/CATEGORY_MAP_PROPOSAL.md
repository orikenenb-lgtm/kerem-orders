# הצעה: מפת קטגוריות חדשה

**סטטוס:** הצעה בלבד. שום קטגוריה לא שונתה — לא ב-DB ולא ברווחית.

## 1. הבעיה

הקטגוריות מגיעות מרווחית (`group_id` → שם קבוצה) כפי שהוקלדו שם לאורך
השנים. בפועל הלקוח רואה בסרגל הסינון ערבוב של קטגוריות אמיתיות עם
קטגוריות תפעוליות/כפולות:

- `חדש 1`, `חדשים 1`, `חדש 4`, `חדש 5`, `סחורה חדשה` — חמש ואריאציות של
  "הגיע עכשיו", שמפצלות את אותה משמעות לחמישה כפתורים.
- `דספלאים מותגים`, `מוצרי טליה מותגים` — שמות פנימיים-תפעוליים.
- `לא פעילים` — קטגוריית ניהול שכלל לא אמורה להופיע ללקוח (אם מוצריה
  `is_active=false` היא ממילא ריקה בקטלוג; אם לא — זו דליפה תפעולית).

הפרונט כבר ממתן חלק מהבעיה (מקבץ את כל קטגוריות ה"חדש" יחד בסרגל), אבל
זה טיפול בסימפטום.

## 2. עקרון הפתרון: שכבת מיפוי, לא שינוי מקור

**לא** לשנות את השמות ברווחית (הם משרתים את התפעול הפנימי ואת המסמכים
שם), אלא להוסיף שכבת תרגום תצוגה:

```
טבלה חדשה (additive): category_map
  source_name  text PRIMARY KEY   -- כפי שמגיע מרווחית
  display_name text NOT NULL      -- מה שהלקוח רואה; NULL/'' = להסתיר מהסינון
  sort_order   int  NOT NULL DEFAULT 100
```

ה-RPCs ‏(`catalog_categories`, `catalog_public_categories`) יעברו דרך
המפה: `COALESCE(m.display_name, p.category)`, קיבוץ לפי שם התצוגה,
והסתרת שורות שמופו ל-NULL. מוצר לא נעלם לעולם — רק הכפתור שלו מתאחד או
מוסתר; חיפוש ממשיך למצוא הכול.

## 3. המיפוי המוצע (טיוטה לאישור הבעלים)

| מקור (רווחית) | תצוגה מוצעת |
|---|---|
| חדש 1 / חדשים 1 / חדש 4 / חדש 5 / סחורה חדשה | **חדש באתר** (מאוחד) |
| דספלאים מותגים | **מותגים** |
| מוצרי טליה מותגים | **מותגים** (או לאשר שם אחר) |
| לא פעילים | *מוסתר מהסינון* |
| כל השאר | ללא שינוי |

שאלות פתוחות לבעלים:
1. האם "חדש 1/4/5" מבחינים בין משלוחים שונים שחשוב להפריד? אם כן — אפשר
   "חדש · אוגוסט", "חדש · יולי" במקום איחוד מלא.
2. מה ההבדל העסקי בין שתי קטגוריות ה"מותגים"?
3. האם יש ב"לא פעילים" מוצרים שעדיין `is_active=true`? (אם כן — לתקן
   ברווחית, זה כנראה סיווג שגוי.)

## 4. מה דורש מה

| שינוי | איפה | סוג |
|---|---|---|
| טבלת `category_map` + עדכון שני RPCs | Supabase (מיגרציה additive + ‏CREATE OR REPLACE) | דורש אישור בעלים; הפיך (DROP + החזרת גרסת RPC קודמת) |
| איחוד אמיתי של קבוצות ברווחית | רווחית עצמה | תפעולי; משפיע על מסמכים פנימיים — לא מומלץ בשלב זה |
| שינוי סדר הצגת קטגוריות | `sort_order` במפה | חלק מאותה מיגרציה |

הפרונט לא ידרוש שינוי כמעט בכלל — הוא כבר צורך את פלט ה-RPCs.

## 5. עד אז

הקיבוץ הקיים של קטגוריות "חדש" בסרגל נשאר; שום מוצר לא מוסתר על סמך
ניחוש.
