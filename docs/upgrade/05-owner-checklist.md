## חלק א — Railway (5 דקות)

**המטרה:** לדעת אם רץ שירות רביעי שכותב למסד עם מפתח service-role.

1. היכנס ל-**railway.app** → Dashboard.
2. חפש פרויקט בשם `kerem-orders` או משהו דומה.
   - **אם אין כזה בכלל** → סיימת. התשובה היא ״אין שירות״. **דלג לחלק ב.**
3. אם יש — פתח אותו וכתוב לי **שתי מילים**: המצב (`Active` / `Crashed` / `Removed`) ותאריך
   ה-deployment האחרון.
4. לשונית **Variables** → חפש `SYNC_ENABLED`.
   - כתוב לי **רק** `true` / `false` / ״לא קיים״.
5. **אל תעצור, אל תמחק ואל תשנה שום דבר שם.** גם אם נראה מיותר.

> ⛔ **אזהרת אבטחה:** בעמוד הזה יושבים ה-service-role key וה-token של רביט. **אל תעתיק לי
> שום ערך משם** — לא בצ׳אט, לא בצילום מסך, לא ״רק כדי שתראה״. מספיק לי `true` או `false`.

**מה אני עושה עם התשובה:**

| מה שמצאת | מה זה אומר |
|---|---|
| אין שירות / לא deployed | רדום, כמו שכל הראיות מראות — ממשיכים |
| רץ, `SYNC_ENABLED=false` | חי אבל לא כותב — ממשיכים, רושם |
| רץ, `SYNC_ENABLED=true` | **עוצרים.** כותב רביעי עם service-role — סוגרים אותו לפני כל פעולה |

## חלק ב — Supabase (10 דקות)

**המטרה:** לוודא שאפשר לפתוח staging בלי לפגוע בשום דבר קיים ובלי לשלם.

1. היכנס ל-**supabase.com/dashboard** → הארגון `orikenenb-lgtm's Org`.
2. **Settings → Billing.**
   - ודא שכתוב **Free**.
   - חפש את המגבלה על **active projects**. יש לך כבר **2 פעילים**. השאלה היחידה: האם
     מותר **שלישי**?
   - כתוב לי: ״מותר שלישי״ / ״לא מותר, התקרה 2״.
3. אם **לא מותר שלישי** — יש שלוש דרכים, ואתה בוחר. **אל תבצע אף אחת עדיין:**

   | דרך | מה זה עולה | מה הסיכון |
   |---|---|---|
   | לשדרג ל-Pro | ~$25 לחודש | אין. **בונוס: Pro כולל גיבויים יומיים אוטומטיים**, שפותר גם את בעיית הגיבוי |
   | להשהות פרויקט פעיל | 0 | **`shahar-zohar-barbershop` פעיל — אם זה אתר חי של לקוח, השהיה מפילה אותו. אל תעשה את זה בלי לוודא.** |
   | staging מקומי (Docker) | 0 | דורש Docker על המחשב שלך, לא בענן |

4. **Database → Backups** בפרויקט של כרם טויס.
   - כתוב לי מה אתה רואה: יש כפתור הורדה? יש גיבויים יומיים? או שכתוב שזה זמין רק ב-Pro?
   - זו התשובה שקובעת כמה דחוף חלק ג.
5. **אל תיצור פרויקט חדש עדיין.** אחרי שתענה, אני אכין את הצעדים המדויקים.

## חלק ג — הגיבוי (10 דקות, וזה החלק הכי חשוב)

**זה הדבר היחיד בכל התוכנית שאני לא יכול לעשות במקומך.** למכולה שאני רץ בה אין חיבור
ישיר לפוסטגרס ואין יציאה ל-Supabase.

1. התקן את ה-CLI:
   ```
   npm install -g supabase
   supabase login
   ```
2. **צא מתיקיית הפרויקט לפני הצעד הבא** — ראה את האזהרה מתחת.
   ```
   cd ~/kerem-backups          # תיקייה מחוץ ל-repo. צור אותה אם אין
   supabase link --project-ref mcdchalyzeqjkkgfeznd
   supabase db dump -f kerem-20260903.sql
   supabase db dump -f kerem-20260903-schema.sql --schema-only
   ```
3. תגיד לי **גודל הקובץ ותאריך** — לא את התוכן.

> 🔴 **אזהרה קריטית — קרא לפני שאתה מריץ.**
> קובץ ה-dump מכיל את **כל 553 הלקוחות שלך** עם שמות, טלפונים, מיילים וח.פ.
> ה-repo שלך הוא **ציבורי**.
> **אל תשמור את הקובץ בתוך תיקיית הפרויקט.** `.gitignore` חוסם `.env` וכמה דפוסי גיבוי,
> אבל **הוא לא חוסם `.sql`** — קובץ dump בתיקיית הפרויקט הוא `git add -A` אחד מלהתפרסם
> לאינטרנט עם כל בסיס הלקוחות שלך.
> שמור אותו בתיקייה נפרדת לגמרי, ורצוי מגובה גם לכונן חיצוני או ענן פרטי.
