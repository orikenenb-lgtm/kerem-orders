# דוח חשיפה: מחירון ציבורי ללא התחברות (`/prices`)

**סטטוס:** דוח בלבד — לא בוצע שום שינוי ב-Supabase, ב-RPC או בהרשאות.
**תאריך:** 2026-08-04 · **ענף:** `collab/kerem-upgrade`

## 1. מה בדיוק חשוף

הכתובת `https://orikenenb-lgtm.github.io/kerem-orders/prices/` פתוחה לכל
גולש, בלי חשבון, ומציגה עבור **כל מוצר פעיל** (~945 מוצרים):

| שדה | חשוף ב-`/prices` | חשוף ב-`/view` |
|---|---|---|
| שם מוצר | ✅ | ✅ |
| תמונה | ✅ | ✅ |
| קטגוריה | ✅ | ✅ |
| זמינות (בוליאני בלבד) | ✅ | ✅ |
| **מחיר מכירה (כולל מע״מ)** | ✅ | ❌ |
| SKU / ברקוד / כמות מלאי מדויקת / מחירי עלות | ❌ | ❌ |

מנגנון: פונקציית SQL בשם `catalog_public_prices()` מוגדרת `SECURITY DEFINER`
ומוענקת ל-role‏ `anon`. טבלת `products` עצמה **אינה** נגישה ל-anon (RLS —
נבדק); החשיפה עוברת דרך ה-RPC בלבד, בכוונה, לבקשת הבעלים (הקישור נועד
להפצה ללקוחות בוואטסאפ בלי לחייב אותם להתחבר).

חשוב לומר ביושר: זה לא "באג" — זה פיצ'ר שהבעלים ביקש. הדוח קיים כדי
שההחלטה תהיה מודעת: **מתחרה יכול לצלם את כל המחירון בדקות**, כולל
בסקריפט אוטומטי (ה-RPC מקבל `lim`/`off` — צריך ~40 קריאות בשביל הכול).

## 2. האם הסתרת הקישור מספיקה? — לא

הסתרת הקישור מהאתר היא "security by obscurity" בלבד:

1. **ה-endpoint נשאר פתוח.** מי שהקישור הגיע אליו פעם אחת (וואטסאפ עובר
   הלאה) — או שסתם מנחש `/prices/` — מקבל הכול. ההסתרה מסתירה מדלת
   הכניסה, לא נועלת אותה.
2. **ה-RPC גלוי בקוד הצד-לקוח.** האתר סטטי; שם הפונקציה
   `catalog_public_prices` ומפתח ה-anon מופיעים ב-JS שכל דפדפן מוריד.
   קריאה ישירה ל-`POST /rest/v1/rpc/catalog_public_prices` עוקפת את הצורך
   בדף בכלל.
3. **ארכיונים וקאש.** הדף כבר נצפה, נסרק ועשוי להיות שמור (Google cache,
   Wayback). מחיקת הקישור לא מוחקת עותקים.

מסקנה: אם יוחלט שהמחירים רגישים — חייבים לבטל את ההרשאה בצד השרת, לא
להסתיר את הדף.

## 3. מה יידרש כדי להגביל מחירים ללקוחות מחוברים בלבד

שינויים נדרשים (כולם בצד Supabase + שני קבצים בפרונט):

1. `REVOKE EXECUTE ON FUNCTION public.catalog_public_prices FROM anon;`
   (או `DROP FUNCTION` אם מעדיפים שלא תישאר בכלל).
2. להסיר את route ‏`/prices` מהאתר (או להפנות אותו לעמוד "התחברו כדי
   לראות מחירים").
3. `landing/app/prices/page.tsx` — מחיקה/החלפה; `PublicCatalog` נשאר
   ל-`/view` (שאינו חושף מחיר גם היום).
4. אין צורך לגעת ב-`catalog_public()` — הוא בנוי בלי עמודת מחיר בכלל.
5. לתקשר ללקוחות שקיבלו את הקישור שהוא מוחלף בקישור `/view`.

הערכת עבודה: ~חצי שעה, הפיך לחלוטין (ה-GRANT חוזר באותה שורה).

## 4. השפעות ביטול הרשאת `anon` — מה חשוב לדעת

`anon` משמש היום לארבעה דברים נפרדים. ביטול גורף של ההרשאות ישבור את
כולם — לכן חשוב לבטל **נקודתית** (רק את `catalog_public_prices`):

| שימוש ב-anon | אם יבוטל נקודתית (רק prices) | אם יבוטל גורף |
|---|---|---|
| `/prices` | נשבר (מכוון) | נשבר |
| `/view` (קטלוג בלי מחירים) | ממשיך לעבוד | נשבר |
| מסך הבית — קריאת `site_settings.min_order_total` | ממשיך | נשבר (יוצג ערך fallback) |
| הרשמה/התחברות (auth עצמו משתמש במפתח anon) | ממשיך | **נשבר לחלוטין** |

לכן: לעולם לא "לכבות את anon" ברמת הפרויקט; רק `REVOKE` על הפונקציה
הספציפית.

## 5. המלצה

ההחלטה עסקית ולבעלים בלבד. שלוש אפשרויות מסודרות:

- **א. להשאיר כמו שזה** — אם הנוחות ללקוחות שווה את חשיפת המחירון
  למתחרים. (המצב היום.)
- **ב. לצמצם** — `/prices` נשאר אבל מציג מחיר רק אחרי "כניסה קלה"
  (למשל מספר טלפון שמאומת מול רשימת הלקוחות). דורש פיתוח.
- **ג. לסגור** — סעיף 3 למעלה. מהיר והפיך.

עד להחלטה — לא שונה דבר.
